# 自研 Harness：运行与状态

只读取本次涉及的部分。这里给出逻辑契约与不变量，不要求每个项目实现全部能力或采用下面的字段名。

## 1. 区分会话、运行和调用

- **conversation/session**：一个对话的有序消息、归属及历史；不是一次 HTTP 连接。
- **run**：处理一轮输入或任务的执行单位，可包含多次模型/工具调用；关联输入幂等键、配置版本、状态、结束原因和必要的检查点。
- **attempt**：一次可能重试的模型请求，保留厂商 request ID，不能把多个 attempt 的输出当作同一段回答。
- **tool call**：模型请求的一次工具动作，关联模型 call ID、参数、执行状态和结果。外部业务操作的幂等身份不能仅依赖模型生成的 call ID。

典型 run 状态可为 `queued → running → completed / failed / cancelled`，需要产品确认时增加 `waiting_for_approval → running`，取消是先 `cancel_requested` 再确认终态。具体状态沿用项目定义，不为无队列系统强加 queued。预算耗尽、输出截断等应有明确结束原因，不能当普通成功。

保证每个 run 只有一个有效终态，晚到的模型/工具结果不覆盖终态。终态是否成功按约定的业务结果判定；工具已部分执行却回答失败，要保留已确认副作用，不能假装整体回滚。

同会话并发请求采用明确策略（拒绝、排队或分支），原子地维护消息顺序与运行拥有权。重发同一个客户端请求不能创建第二次业务执行；同一幂等键携带不同内容应按契约拒绝冲突。去重键的作用域包括真实用户/租户边界及有效期。

## 2. 一个受控的执行循环

在现有架构内实现以下语义，不机械复制循环结构：

1. 确认身份、会话权限、输入和 run，固定本轮 prompt/工具 schema/模型配置版本。
2. 每次调用前检查取消、截止时间、步数与预算，构造合法上下文。
3. 通过 adapter 调用模型，消费结构化事件。自然语言回答、工具意图、拒绝、截断和协议错误分别处理。
4. 有工具意图时，先完整收集调用与参数，再解析和服务端校验；通过权限/审批/预算后执行。结果按 call ID 回填，成功和失败都保留准确状态。
5. 工具结果作为数据进入下一轮；模型返回最终回答或规则要求终止时结束并保存结果/原因。

步数、模型调用次数、工具调用次数、重试、墙钟时间和 token/成本分别可有限额，按任务选用并说明计数定义。系统、SDK、工具各自重试的总和必须纳入 run 总预算，不能叠成无界循环。预算不够时选择已约定的失败或部分结果，不让模型自行放宽额度。

本地 token/价格只能估算时明确标注；需要严格金额上限的产品应有保守预留、并发预算占用及供应商侧限制，不能把延迟到账的 usage 当硬实时保证。

## 3. 工具执行和副作用

工具定义应足够明确：用途、输入 schema、输出含义、读/写性质、错误与需要的权限。只暴露当前上下文可用工具；执行时仍重新授权，不能以“已给模型看见工具”替代校验。

模型参数和工具结果都不可信。服务端限制参数类型/长度/允许值，校验业务资源归属，使用安全的 I/O 实现；模型不得覆盖 actor/tenant 或获得凭据。带网络/文件/命令能力的工具按实际范围限制目的地和执行权限。RAG 文本、网页和工具结果中的指令不能提升权限。

需要产品内确认的写操作，在展示具体参数后持久化待确认意图；确认须绑定用户、操作、参数版本和有效期。恢复时重新检查权限，参数变化后旧确认失效。是否需要确认由产品规则决定，不把开发者编码操作与最终用户的工具审批混为一谈。

**写操作的重试与恢复边界：**

- 使用稳定的业务操作 ID/幂等键并保存执行意图和结果；同一操作重试复用身份，新的合法操作不能被错误去重。
- 外部系统已执行、本地来不及记结果是实际崩溃窗口。优先复用下游幂等键或查询/对账接口；结果未知时进入待核实/人工处理，不能盲目重试或宣称 exactly-once。
- 本地事务不能原子覆盖第三方副作用。需要可靠事件投递时按项目使用 outbox 等机制，但传输去重仍不等于业务操作幂等。
- 可并行的只读/独立工具在限额内并行；有依赖、同资源写入或产品确认的操作按约束排序。并行结果按各自 call ID 匹配，不能依到达顺序配对。
- 工具超时/取消不证明远端动作未发生。记录已知结果和未知部分；补偿仅在业务明确支持且获授权时执行。

## 4. 上下文与记忆

组装顺序和信任边界明确：系统规则、工具定义、用户输入、会话历史、相关检索/工具数据。用结构标识外部内容只能辅助模型理解，权限控制仍在代码。

在发请求前预留输出空间和必要的工具开销，超长工具结果做有界裁剪/摘要并保留来源，不能无限回灌。裁剪/压缩不拆散厂商要求配对的工具调用与结果，不丢失未完成动作、关键用户限制和已确认事实。摘要是派生信息，不能代替原始业务数据或运行检查点；压缩后用长对话评测验证信息保留。

会话历史、运行检查点、长期记忆分开建模。只有明确需要跨会话记忆时增加记忆写入、检索、归属、保留期及删除传播；检索过滤与缓存隔离在服务端执行，不依赖模型忽略越权资料。模型不支持恢复所需的供应商专用内容时，不能跨厂商直接重放原协议消息。

## 5. 流式协议、取消与恢复

内部事件可按项目采用 run 开始、文本增量、工具意图/结果、usage、终态/错误等类型，关联 run 与 attempt；不直接把厂商原始流协议当作稳定客户端契约。重连需要回放时才加入可持久化的单调事件 ID 和游标。

明确哪些文本是最终可见答复，哪些仅是状态；内部推理内容不默认作为客户端事件或日志保存。工具参数增量不是已执行结果，不在 JSON 半成品阶段执行工具。

TCP/SSE 分片可能拆开 UTF-8、JSON 和事件边界；解析器处理碎片、重复、未知事件和异常结束。流已经发送 HTTP 头后，失败以约定的流错误/终态表达，不能试图再改 HTTP 状态码。明确无终止标记的 EOF 如何处理；不能无条件判定完成。

传输断开采用产品约定的“继续后台运行”或“请求取消”；两者不能混同。重连时只回放既有事件，不重新执行工具。取消向模型与工具传播，停止新调度，处理迟到回调；不可中止的外部操作保留结果未知或最终确认状态，不承诺撤销。

有跨进程续跑要求时持久化足以恢复的 run 状态、待执行/已完成动作和配置版本，并定义恢复所有权。非确定性调用的结果或安全重执行边界要可判定；恢复不等于从头重新生成。测试崩溃在工具执行前、远端执行后、本地结果持久化前的窗口。只保存 messages 的实现不能宣称完整续跑。

客户端慢消费要有缓冲上限、背压/断开策略及连接清理，避免无界队列。保存最终消息、run 终态与发布终态事件需有一致性方案；不能发“完成”后落库失败却仍让查询显示成功。

## 6. 可观测性与针对性验证

沿用项目 tracing，关联 request/conversation/run/attempt/tool；记录真实模型/API、prompt/工具版本、耗时、重试、结束原因、token usage 的实际/估算/未知及成本计价来源。区分首个业务事件耗时、首 token 耗时和总耗时；高基数字段放 trace，不直接作 metrics 标签。

默认不记录完整用户输入、工具敏感结果或内部推理；排障确需正文时按项目策略脱敏、限制访问和保留期，密钥永不入日志。追踪信息不能替代持久化恢复数据。

只对本次相关不变量做验证：重复输入只产生一次执行、跨用户会话拒绝、取消后无新工具、预算终止、参数完整后才执行、并发 call ID 配对、晚到结果不改终态、恢复不重复写。完整评测选择见 [evaluation](evaluation.md)。
