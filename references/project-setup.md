# 项目接入

仅在首次接入或路径不清时读取；技能可用不表示当前目录就是业务项目。

## 找到项目事实

优先采用用户指定路径，再通过适用的 `AGENTS.md`、服务 README、依赖清单、启动入口和部署配置判断边界。只查本轮需要的配置名，不打印密钥值。技能安装目录不能用于推断业务目录。

局部确认已有语言/框架、请求入口、鉴权与租户来源、会话存储、模型客户端、工具执行、提示词、测试和评测命令。尚不存在的能力写明未建立；接口类存在但没有实际调用者，不算已接入。

已有项目不迁目录、不新建第二套后端。空工程在 scaffold 中按团队约束选最小方案；无约束时可推荐熟悉的常规 Web 栈并说明理由，不把推荐写成用户已指定。

## 文件归属

下列为默认位置，项目已有等价文件时直接沿用：

```text
<project>/
  <existing-service-root>/    # 代码、测试、提示词、真实运行命令
  docs/prd/                  # 当前目标、验收、交付缺口
  docs/changes/              # 本次语义变更
    archive/                 # 已结束的历史变更
  docs/architecture/        # 值得保留的工程设计与取舍
  evals/                    # 项目需要评测时的用例、评分与结果引用
```

这不是建目录清单。普通功能不新增项目索引、注册表或多份活跃台账。PRD 写用户行为；接口字段写现有 OpenAPI/事件 schema；模块与状态所有权写架构文档；大批评测结果留在项目已有产物位置，PRD 只引用摘要和证据。

用户要求初始化项目协作约定时才补最小 `AGENTS.md`，保留原有约束，只记录项目差异、真实命令和 `$agent-backend-workflow` 用法；不要复制本技能全文。升级技能不自动改项目架构、技术栈或规则。

默认排除缓存、生成物与历史归档；定位明确需要的历史问题时按需读取。项目文档不能依赖本机技能路径，项目运行也不依赖技能包。使用项目已有版本控制，不自动初始化、提交或发布仓库。
