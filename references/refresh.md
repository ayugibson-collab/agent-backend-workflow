# 局部需求刷新

适用：改变现行规则、限制、工具权限、模型支持范围或 PRD 结构。恢复既定行为用 [fix](fix.md)。

1. 找到拥有该规则的最新 PRD、相关验收和真实实现。检查关联接口、提示词、工具策略、模型配置及评测用例，只读实际相关范围。
2. 有语义变化时用一份 [CHANGE 模板](../assets/templates/CHANGE.md) 写完整差量；区分共同产品规则、真实厂商差异和本次实施范围。用户明确的新规则直接采用，额外发现的产品冲突才澄清。
3. 按 [PRD 演进](prd-evolution.md) 重读基线并合并，保留无关条件及独立编辑。用户只要求候选方案时不改当前目标；纯结构整理不强制 change。
4. 更新相关验收和受影响缺口。涉及模型、prompt、工具 schema、上下文或路由时，指出哪些评测需要重跑；只做文档任务不执行代码或模型调用。未知实现状态写待核实。
5. 已要求实现就进入 [build](build.md)；否则完成文档即止。余留工作已写入当前 PRD 后可归档 change，更新引用。

例如把“达到运行预算后直接报错”改成“停止新工具调用并返回已确认结果”，需保留原权限与数据约束，并验证预算耗尽后的结束原因、部分结果和禁止继续执行的行为；不能仅改一行提示词后宣称后端规则已生效。
