# 第三方 LLM 接入

用于新增/更换厂商、模型、API/SDK 版本或修改 adapter。不指定某家为默认，也不把“接口兼容”视为已经验证。

## 先核对本次模型能力

读取所选厂商的官方 API 文档、已锁定 SDK、现有客户端及真实配置，记录核对日期与具体模型/API 版本。动态模型别名不能当作固定版本；记录实际响应返回的模型标识（若有）。不从宣传页推断全部型号能力。

只调查当前需求所需能力，按模型分别标记“已验证支持 / 官方声明未实测 / 不支持 / 未知”：

- 消息角色、内容块、多模态（涉及时）、system 指令位置、工具结果回传方式。
- 工具 schema 子集、tool choice、并行调用、调用 ID、流式参数增量和正常结束标记。
- 结构化输出、严格 schema、拒绝和截断表示；JSON 可解析不代表满足业务 schema。
- 上下文/输出限制、采样参数及不兼容组合、reasoning 等供应商字段的传递约束（涉及时）。
- 流式 usage 是否出现、缓存/推理 token 计费口径、限流、超时、取消与错误体。
- 有相关约束时核对区域、数据用途/保留及目标 endpoint，不能未经约定切到不同数据边界的厂商。

能力记录可放已有配置、测试说明或架构文档，不强制新建平台级注册表。缺少必需能力时明确拒绝/标为不支持，或按已接受产品方案实现显式降级；不能静默删字段、把工具调用改成普通文本却声称等价。

## Adapter 的最小契约

沿用项目类型；若从零设计，覆盖以下信息即可，不复制成通用模型平台：

- 请求：结构化 messages、工具定义、所需输出格式、生成参数、deadline/取消信号与追踪信息。
- 输出：文本增量、完整工具调用/参数增量的结构、结束原因、拒绝/截断、usage 和厂商 request ID。
- 错误：认证/权限、无效请求、能力不支持、限流、暂时不可用、超时/连接中断、协议解析错误。保留脱敏厂商错误以便定位，不把业务字段或密钥回传客户端。
- 能力：Harness 能判断本次所需特性是否可用；重要厂商差异通过显式字段/受控扩展表达，不在 Harness 到处判断厂商名。

用完整结构保留工具 call ID 与结果配对，避免把全部消息压成一个字符串。供应商要求回传的内容块、签名或其他状态只在 adapter 内按文档处理，不随意丢弃、跨厂商复用或公开记录。不要求获取模型未提供的内部推理。

流解析考虑文本与多工具增量交错、多个内容块、分片 JSON、结束后 usage、空响应、拒绝、长度截断、异常 EOF 与未知事件。仅在消息/调用结束且参数合法后允许执行工具。

## 超时、重试和降级

将连接、首事件/空闲、单次调用和整个 run 截止时间区分，按实际客户端能力配置。SDK 内建重试、网关和 Harness 必须有明确归属，共享有界预算，避免重试相乘。

- 认证、参数/schema、必需能力不支持通常直接失败；修改请求是新策略，不能当作无条件重试。
- 对确认可重试的限流/临时故障使用有限退避与抖动，遵循供应商 Retry-After，同时服从 run 剩余预算与取消。
- 模型调用重试会增加成本且输出可能改变，即使 temperature 为 0 也不保证相同；不要把模型重试等同于重放业务工具。
- 已向客户端输出部分文本时，不把新 attempt 的文本追加到旧答案后。按协议明确终止，或显式重置/开启新 attempt，并让客户端能辨识替换关系。
- 已有工具副作用时，从已确认状态继续或结束；不得通过整轮重新生成来规避错误。结果未知的写工具按 Harness 的核实规则处理。
- 只有已配置且能力、权限、数据边界满足要求的备用模型才能接管。切换时重建有效上下文，记录降级原因、实际模型和相关质量影响；无法保持协议语义则结束并提供可理解的失败。

客户端配置通过项目配置/密钥管理注入，示例只写环境变量名。公开请求不能任意覆盖服务端 endpoint、认证头和模型路由，避免把模型代理变成任意转发器。

## 接入验证

按本次路径构建合同测试：请求编码、消息/工具回传、碎片事件解析、结束/拒绝/截断映射、usage 缺失、错误分类、重试和取消。不需要每家厂商在每个普通任务中全量跑。

有凭据且在任务允许的数据/费用范围内，运行最小真实冒烟：普通回答、所需流式、一次所需工具/结构化输出、结束与 usage。再用代表性对话跑质量回归。不要通过故意刷限流或执行真实高风险业务来验证错误场景。

报告明确模型/API/SDK、配置版本、实际命令与环境、合同测试和真实调用各自结果。Fake adapter 或单纯 SDK import 成功不能证明接入完成。
