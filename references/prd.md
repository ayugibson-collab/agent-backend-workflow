# 新需求 PRD

适用：把一个聊天 Agent 目标变成可开发、可验证的规则。已有主题局部变化用 [refresh](refresh.md)。

## 从用户结果起步

先查最新相关 PRD、真实接口、会话行为和已有评测，保留输入中的数字、例外、限制及否定要求。确认用户要解决什么问题、本轮覆盖哪些能力/渠道/厂商，以及一个完整对话如何结束。不要把代码缺陷认作产品规则，也不要从“Agent”一词推导出自动执行、RAG 或多 Agent。

只对本次涉及的行为补充说明：

- 聊天：身份与会话归属、多轮信息如何延续、流式/非流式结果、停止生成、重复提交、失败后的可操作项。
- 工具：何时查询/执行、必须满足的身份权限、哪些动作需要产品内确认、成功依据来自哪里。外部动作未成功时不能回答“已完成”。
- 运行：何时结束、耗尽预算或超时后的结果；是否要求断线继续、跨进程恢复。断线、取消和删除会话是不同产品行为。
- 资料与记忆：仅在涉及检索/长期记忆时明确数据范围、来源、更新/删除、隔离和引用要求；不默认永久记住用户输入。
- 模型：支持的厂商/模型范围，故障时允许重试、降级还是失败；切换是否改变结果、数据去向或产品承诺。

内部类名、数据库表和 SDK 选型放技术设计。响应时间、成功率、成本限制属于产品约束时才写数值，并给出来源；没有约定就标为建议/待定，不虚构 SLA。

## 写成可验证的要求

用一份 [CHANGE 模板](../assets/templates/CHANGE.md) 记录新语义，注明规则适用范围和本轮实现范围。新增主题可以在 change 中先写完整规则；已有主题保留仍成立的前提和例外。

验收分两类，按实际需要采用：

- **确定性行为**：条件 → 操作 → 可观察输出/状态/副作用。例如无权访问会话时，拒绝读取且不触发模型调用；取消生效后不调度新工具。
- **模型效果**：用例范围、期望结果、禁止行为、评分方式和验收口径。例如查询状态时调用正确只读工具，答案与返回事实一致，不编造物流节点。通常不匹配固定措辞或唯一工具轨迹。

需要效果门槛时，关联 [评测指南](evaluation.md)：数据集版本、基线、重复次数、样本数、允许退化和预算。尚未确定的门槛不能作为已承诺验收；确定性规则不依赖 LLM 评分。

## 同步与结束

用户明确要求形成/更新当前 PRD，或已要求实现明确新行为时，按 [演进规则](prd-evolution.md) 同步到主题 PRD，可使用 [PRD 模板](../assets/templates/PRD.md)，不再索要重复批准。仅候选方案留草案；阻塞决策不能冒充已接受规则。

当前 PRD 区分已接受目标、实际实现及验证缺口。某厂商尚未支持必需能力属于交付缺口，不擅自改成产品例外。文档任务结束可归档本次变更；同时要求开发则继续 [build](build.md)。
